# Необязательная локальная смысловая проверка

Смысловой режим расширяет проверку связи англоязычной публикации с запросом:
модель сравнивает тексты и может находить близкие формулировки без буквального
совпадения. Группировка остаётся TF-IDF + NMF. Для трёх известных направлений
сохраняются предметные ограничения; сходство не отменяет проверку исполнителя,
отрицаний и подтверждающих цитат.

По умолчанию выбран `lexical`: прежние правила без весов модели. `semantic`
включается явно и использует заранее подготовленные локальные веса.
Приложение не скачивает модель при открытии UI или запуске анализа.

## Подготовка модели

Из корня проекта, в окружении Python 3.13:

```sh
.venv/bin/python -m pip install -r requirements/semantic.lock
.venv/bin/python -m scripts.install_ml_model
```

Эти две команды требуют интернета. Установщик сохраняет модель в
`storage/models/e5-small-v2` внутри проекта и проверяет фиксированные SHA-256.
Каталог модели не зависит от каталога базы backend (`--data-dir`). Для другого
расположения:

```sh
.venv/bin/python -m scripts.install_ml_model --model-dir "/путь/к/модели"
```

На Windows замените `.venv/bin/python` на `.venv\Scripts\python.exe`.
На компьютер без интернета можно перенести уже проверенный каталог модели
целиком; зависимости необходимо заранее установить в его Python-окружение.
Окружение `.venv` между компьютерами не переносится. Дальнейший анализ
использует только локальные файлы, исходные публикации никуда не отправляются.

## Проверка установленной модели без сети

```sh
.venv/bin/python -m scripts.check_local_model --output storage/local-model-smoke.json
```

При другом расположении весов добавьте `--model-dir "/путь/к/модели"`.
Без `--output` отчёт печатается в терминале; существующий файл не перезаписывается.
[Проверка](../../scripts/check_local_model.py) использует
[фиксированные синтетические тексты](../../tests/fixtures/local_model_cases.json):
пять английских запросов, десять простых примеров и два сложных фотонных случая.
Скрипт не скачивает веса и не запускает сбор публикаций.

Проверяются размерность 384, конечность и единичная норма векторов,
повторяемость двух расчётов, а также порядок пяти простых пар `smoke_expected`.
Случаи `adversarial_unvalidated` получают scores и решения лексических правил,
но не влияют на успешность проверки. У них нет независимой научной разметки.
Порог не подбирается; precision/recall не вычисляются. Код возврата: `0` —
техническая проверка пройдена, `1` — сравнение или повторяемость не прошли,
`2` — ошибка входа, весов или зависимостей.

Проверенный запуск 9 сентября 2026 года на macOS arm64 / Python 3.13.7 прошёл
пять простых пар; embeddings повторились с допуском `1e-6`. Проверка заняла
около 0.49 с, включая загрузку модели; peak RSS процесса — около 308 МиБ.
Это один локальный замер на 12 коротких текстах, не оценка памяти/времени
анализа большого корпуса или NMF. В JSON отдельно записаны время загрузки,
inference и повтора, CPU-время, доступный peak RSS, SHA-256 текстов, модель
и отпечаток результата без изменяющихся замеров времени.

У синтетических примеров электронного вычисления с фотонным interconnect
и только будущего применения сходство оказалось около `0.876` и `0.869`.
Оба лексических решения — `scope_not_established`. Эти значения иллюстрируют,
почему высокое сходство само по себе не подтверждает исполнителя или
реализованное применение и почему предметные ограничения сохраняются.

## В интерфейсе

Откройте JSON-корпус или сохранённую историю на вкладке «Тренды · MVP».
Включите **«Смысловая проверка (локальная модель)»**, затем нажмите
**«Анализировать»**. При необходимости укажите путь кнопкой **«Каталог модели…»**. Переключатель по
умолчанию выключен; смена режима применяется к следующему анализу.

На вкладке «Качество данных и методика» показаны модель, ревизия, порог,
количество оценённых текстов и исследований, добавленных только по сходству.
Полные решения и сведения о модели сохраняются в `semantic_relevance`
экспортированного JSON версии 2. Старые результаты без этого необязательного
поля продолжают открываться.

## Через CLI

```sh
.venv/bin/python -m app.ml \
  --snapshot storage/ml-validation/corpus-portable.json \
  --relevance-mode semantic \
  --start-year 2020 --end-year 2025 \
  --output storage/trends-semantic.json
```

Для другого каталога весов добавьте `--model-dir "/путь/к/модели"`.
Этот параметр допустим только с `--relevance-mode semantic`.
Параметры `--history-id` и `--data-dir` работают так же, как в обычном режиме.
Для прежних правил укажите `--relevance-mode lexical` или опустите параметр.
Выходной файл должен иметь новое имя.

Если веса отсутствуют или повреждены, анализ завершается понятной ошибкой.
Повторите подготовку модели в новый каталог и установите зависимости из
`requirements/semantic.lock`. Автоматического скачивания и скрытого
перехода на лексический режим нет. При необходимости пользователь может явно
выключить смысловую проверку и запустить прежний режим.

## Модель и воспроизводимость

Используется английский encoder [intfloat/e5-small-v2](https://huggingface.co/intfloat/e5-small-v2), ревизия
`ffb93f3bd4047442299a41ebb6fa998a38507c52`. ONNX-веса занимают 133 093 468 байт
(около 133 МБ), tokenizer — 711 396 байт. Это размер файлов, не предел RAM
всего анализа; импорт корпуса, embeddings и NMF требуют дополнительной памяти.

Параметры фиксированы: ONNX CPU float32, префикс `query: ` для запроса и
`passage: ` для документа, усреднение токенов с учётом attention mask,
L2-нормализация, cosine similarity, максимум 512 токенов, batch 8,
2 intra-op и 1 inter-op поток. Документ представлен заголовком и первыми
6000 символами очищенной аннотации; затем текст ограничивается tokenizer.
Отсутствующие части публикации не восстанавливаются моделью. В результате
сохраняются версия модели и параметры проверки для повторного анализа.
Телеметрия ONNX отключается до импорта runtime. Отмена проверяется между
пакетами; уже выполняющийся вызов ONNX сначала завершается.

Структурную сверку результата с исходным корпусом можно выполнить отдельно:

```sh
.venv/bin/python -m tools.audit_ml_result \
  --snapshot storage/ml-validation/corpus-portable.json \
  --result storage/trends-semantic.json \
  --output-base storage/trends-semantic-audit
```

При нестандартном расположении весов добавьте `--model-dir "/путь/к/модели"`.
Для смыслового результата аудит заново вычисляет локальные similarity scores
и подготовку корпуса, но не обучает NMF. Это проверка воспроизводимости и
целостности; она не заменяет содержательную оценку научных утверждений.

## Границы результата

Порог `0.82` — исследовательская настройка, не калибровка по независимой
разметке. Сходство — **не вероятность релевантности**, качества исследования
или будущего успеха технологии. Тематически близкая публикация может описывать
отрицательный результат, другой механизм или предполагаемое применение.
Если хотя бы одно исследование корпуса допущено только смысловой проверкой,
все его группы остаются предварительными до проверки. Добавление влияет на общий
TF-IDF/NMF и знаменатели годовых долей, в том числе на группы, состоящие только
из работ, прошедших лексические правила. Это отражено флагом `corpus_requires_review`.
Предметный фильтр по-прежнему может отправить группу в отклонённые.

Поддерживаются английские запросы и публикации; русские алиасы известных
направлений сохраняются. Автоматического перевода и многоязычной модели нет.
Добавление по смысловому сходству блокируется, если в метаданных явно указан
неанглийский язык или более **60% букв очищенной аннотации** относятся к
нелатинским письменностям (`MAX_NON_LATIN_LETTER_SHARE = 0.6`). Это проверка
всей очищенной аннотации до ограничения её длины; ровно 60% сами по себе
блокировку не вызывают. Противоречащие языковые метаданные у одинакового текста
также не обходятся выбором его другой записи.

Язык автоматически не определяется: неизвестный язык текста, написанного
латиницей, остаётся непроверенным. Латинские буквы в запросе тоже не доказывают,
что он английский. Причины пропуска смысловой оценки и счётчики сохраняются
в `semantic_relevance`; прежний лексический допуск не изменяется. Поэтому
документ, прошедший старые правила, может остаться в корпусе без semantic score.

Для произвольного направления нужен соответствующий корпус; смена запроса
не превращает имеющиеся публикации в данные другой темы. Модель не исправляет
неполный сбор, пропуски аннотаций, неверные даты и версии исследований.

Прежний лексический контроль и ретроспектива не оценивают новую смысловую
модель. Корректность software-тестов и показанные примеры не устанавливают
независимую precision/recall. Для такой оценки нужны новые размеченные данные,
включая не использованные при настройке направления, пары версий и трудные
отрицательные случаи. Новизна и стадия технологии по-прежнему требуют проверки.
Для исторической оценки отдельно проверяются дата и состав предобучения encoder:
фиксированная ревизия сама по себе не исключает знакомства модели с тестовыми
публикациями или сведениями, появившимися после исторической даты отсечения.
