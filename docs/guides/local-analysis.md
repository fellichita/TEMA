# ML-часть для демонстрации: версия 1.6.0

Действующий конвейер — `local-mvp-nmf-1.6.0`, формат **результата** — JSON
`schema_version: 2`. Формат входного исторического снимка остаётся `schema_version: 1`.
Этот документ описывает согласованную область сдачи. Числа и состав выдачи из
прежних аудитов относятся к указанным в них версиям, а не к текущему расчёту.

В 1.5.0 добавлен необязательный [режим с локальными весами E5](semantic-model.md).
В 1.6.0 исправлены учёт дополнительных материалов, полнота сборов и обработка
некорректных входных данных. Подтверждённый supplement хранится среди версий
основной статьи и не увеличивает число независимых исследований. Форматы снимка
и результата, профили направлений и веса рейтинга сохранены.

## Что сдаётся

Основной продукт — настольное приложение Tkinter: направление → сохранённые
публикации → группировка → динамика → отбор → карточки и источники. CLI и JSON
позволяют воспроизвести расчёт. Реальная интеграция с банковской платформой,
HTTP API и серверное развёртывание в эту версию не входят.

Анализ выполняется локально на CPU. Базовый режим `lexical` не требует весов;
режим `semantic` использует отдельно установленные веса английского encoder.
Внешний LLM и GPU не требуются. Сетевой сбор выполняется отдельно, во время
подготовки корпуса. Кнопка «Сбор через интернет» и открытие внешней страницы
источника требуют сети; для автономной демонстрации они не нужны.

Методика и параметры сохранены: TF-IDF + NMF, не более 32 тем, `random_state=42`,
`max_iter=250`, `tol=0.001`, порог концентрации 0,2. Число тем может быть меньше
32 на небольшом корпусе. Веса рейтинга — рост 35%, недавнее первое наблюдение
20%, устойчивость 15%, связность 20%, объём свидетельств 10%. Рейтинг не является
вероятностью успеха, доказательством новизны или инвестиционной рекомендацией.
Организации, HHI, увеличение числа кластеров и порог 0,35 отменены и не добавляются.

## Направления и данные

Профили находятся в `app/ml/directions/*.json`. Они задают русские названия,
псевдонимы, английский запрос и проверяемые оси. Подготовлены три локальных
корпуса для содержательной проверки:

| Направление | Русский ввод | Локальный входной JSON |
|---|---|---|
| Photonic neuromorphic computing | Фотонная нейроморфика | `storage/ml-validation/corpus-portable.json` |
| Quantum reservoir computing | Квантовые резервуарные вычисления | `storage/validation-quantum/corpus.json` |
| DNA data storage | Хранение данных в ДНК | `storage/validation-dna/corpus.json` |

Корпуса содержат реальные публикации. Их покрытие ограничено запросом, датами,
наличием аннотаций и состоянием сбора; наличие корпуса не означает полную выборку
научного направления. Рабочие снимки в `storage/` исключены из Git, но их
проверяемая архивная копия поставляется в
[data/offline-storage](../../data/offline-storage/README.md).
После клонирования выполните `python -m scripts.restore_storage`, как показано
ниже; восстановление проверяет контрольные суммы и не заменяет существующие
рабочие файлы. Собственный снимок можно открыть через диалог «Открыть JSON-корпус…».

Другой ввод допустим: для ненастроенного направления применяется общий
лексический фильтр с предупреждением «профиль направления не настроен,
проверка релевантности ограничена». При явно выбранном режиме `semantic`
к нему добавляется смысловая проверка; если корпус расширен только по сходству,
все его группы остаются предварительными. Известные русские названия переводятся
по конфигурации. Неизвестный русский запрос не переводится автоматически;
при явно запущенном сетевом сборе источник получает исходную строку.

Русский ввод не означает многоязычную обработку публикаций: текущие лексические
правила и TF-IDF настроены на английские названия и аннотации. Китайская
аннотация с нейроморфным содержанием может быть пропущена, если английского
подтверждения нет. В фотонике также возможны пропуски при описании механизма
через photomediated или photodetector без терминов текущего словаря. Эти
ограничения полноты зафиксированы отдельным контролем, а не скрыты за числом тестов.

Автономный анализ требует подходящего сохранённого корпуса. Новый запрос
без соответствующих данных не создаёт публикаций. Тема запроса должна совпадать
с темой снимка после разрешения известных псевдонимов: нельзя выдать фотонный
корпус за ДНК или квантовые вычисления простым переименованием поля.

## Как читать результат

| Поле JSON | Раздел интерфейса | Правило |
|---|---|---|
| `candidates` | TOP трендов | До 15 групп, прошедших условия направления, свидетельств, устойчивого роста, сопоставимого покрытия и объёма |
| `preliminary_signals` | Предварительные сигналы | Группы, для которых рост, исполнитель или поля карточки подтверждены недостаточно |
| `established` | Крупные темы | Более 8% работ доступного корпуса за выбранное окно |
| `excluded_off_direction` | Отклонено фильтром | Группы, не прошедшие проверку направления, с причинами |

Предварительные сигналы не дополняют основной TOP. При недостатке доказательств
основной список короче 15 или пуст. В частности, неполное покрытие не позволяет
утверждать сопоставимость роста. В таком случае пользователь всё равно может
рассмотреть предварительные сигналы и крупные темы. Интерфейс автоматически
открывает первый непустой раздел; экспорт сохраняет все разделы.

В режиме `semantic` наличие хотя бы одной публикации, допущенной только по
сходству, оставляет все группы расширенного корпуса предварительными, даже при доле выше 8%; отклонение
предметным фильтром по-прежнему имеет приоритет. Причина записана как
`semantic_scope_requires_review`; подробности модели и решений — в необязательном
поле `semantic_relevance` результата и групп.

Разбиение выполняется до ограничения TOP. Карточка не дублируется между разделами.
В `selection` записаны раздел, причины, `window_document_share` и порог 0,08.
Доля считается по сумме работ внутри окна, а не по числу всех ранних и поздних
документов группы. Ровно 8% не означает превышение порога. `established` здесь —
эвристика большого объёма в доступной выборке, а не утверждение о мировой зрелости.

Для фотонной нейроморфики `execution.evidence_level` различает прямое
свидетельство исполнения (`direct`) и тематическое упоминание (`nominal`).
Группы только с `nominal` не входят в главный TOP и располагаются после групп
с прямыми свидетельствами. Баллы и веса при этом не изменяются. Обучение на GPU
совместимо с исполнением оптикой; фоновое перечисление альтернатив не подтверждает
исполнителя. Частота упоминаний носителя служит диагностикой, а не безусловным запретом.
Для остальных направлений правило оптического исполнителя обозначено
`not_applicable`; релевантность проверяется их собственными профилями.

`direction_guard.axis_check` принимает `supported`, `partial`, `off_direction`.
Оно описывает проверку осей направления, а не стадию технологии. `stage` сохраняет
отдельный смысл и значение `requires_review`. Лексические профили и проверка
исполнителя не заменяют экспертную оценку статьи и могут ошибаться при неявных
формулировках, сложных связях и неоднозначных терминах.

## Карточки, цитаты и даты

Каждая карточка содержит название, проблему, преимущество, пример исследования,
метрики, источники и ограничения. Краткие пояснения `explanations` написаны
по-русски. Автоматические названия и подтверждающие цитаты остаются на языке
источника; цитаты не переводятся и не переписываются.

После извлечения выполняется отдельная проверка назначения и модальности
фрагментов. `evidence_annotations` указывает характер утверждения: например,
результат источника, симуляция, предложенный подход, перспективное применение
или библиографическая ссылка. Исследование по названию не становится доказанным
физическим экспериментом. Неподходящий фрагмент сохраняется в `rejected_quotes`
для аудита; выбирается другой подходящий фрагмент либо поле остаётся пустым.
Происхождение цитаты и её соответствие полю проверяются отдельно.
Смешанное свидетельство симуляции и физического эксперимента имеет отдельную
метку `simulation_and_experiment`. Описание ограничения не становится результатом
симуляции только из-за упоминания simulation software или theoretical phase.
Библиографический пример без содержательного фрагмента оставляет группу
предварительным сигналом, даже если остальные условия основного TOP выполнены.

Явно отозванные записи исключаются по доступным признакам отзыва. Неявные ошибки
метаданных, научную достоверность и полноту сведений об отзыве система не гарантирует.
Остатки LaTeX и неполные автоматические словосочетания в названии отмечаются
ограничениями; исходные цитаты ради внешнего вида не исправляются.

| Метрика | Значение |
|---|---|
| `first_observed_year_in_corpus` | Самое раннее подтверждённое наблюдение среди документов группы в доступном корпусе |
| `first_observed_year_in_window` | Самое раннее наблюдение группы внутри выбранного окна |
| `first_observed_year` | Сохранённый совместимый псевдоним года в корпусе |

Оба новых года подписаны в интерфейсе. Год до начала окна может присутствовать
в первой метрике. Это не гарантированный первый год упоминания в мире и не дата
изобретения. Отсутствующее наблюдение не заполняется произвольным годом.

## Запуск

Подготовьте окружение по [основной инструкции](../../README.md). Следующие
команды выполняются из корня проекта. Анализ сохранённых данных работает
без интернета:

```sh
.venv/bin/python -m scripts.restore_storage
.venv/bin/python -m app.main --data-dir storage/mvp-demo
```

На Windows путь к интерпретатору — `.venv\Scripts\python.exe`.
Окружение `.venv` между разными компьютерами не копируется: его нужно подготовить
на целевой системе до автономной демонстрации.

Во вкладке «Тренды · MVP» кнопка «Локальное демо» открывает фотонный корпус.
Для квантового направления и ДНК откройте соответствующий JSON из таблицы выше.
После расчёта выберите раздел, изучите карточку и «Качество данных и методика»,
затем сохраните результат JSON. Тексты ссылок доступны без открытия сайтов.

Три независимых воспроизводимых запуска CLI, окно 2020–2025:

```sh
.venv/bin/python -m app.ml --snapshot storage/ml-validation/corpus-portable.json --topic "Фотонная нейроморфика" --start-year 2020 --end-year 2025 --output storage/delivery-photonic.json
.venv/bin/python -m app.ml --snapshot storage/validation-quantum/corpus.json --topic "Квантовые резервуарные вычисления" --start-year 2020 --end-year 2025 --output storage/delivery-quantum.json
.venv/bin/python -m app.ml --snapshot storage/validation-dna/corpus.json --topic "Хранение данных в ДНК" --start-year 2020 --end-year 2025 --output storage/delivery-dna.json
```

Выходное имя должно быть новым: CLI не перезаписывает существующий файл.
Вместо снимка можно указать `--history-id ID --data-dir PATH` для сохранённой
завершённой истории. CLI и GUI не должны одновременно владеть одной базой SQLite.
Период — 4–30 завершённых лет; незавершённый текущий год в динамику не включается.
Снимок ограничен 300 МБ, стандартный предел входа — 20 000 записей.

Отмена проверяется между этапами; внутри выполнения NMF она ожидает окончания
текущего этапа. Расчёт выполняется вне основного потока Tk, поэтому просмотр
документов и интерфейс продолжают работать.

## Контракт интеграции и воспроизводимость

Точка вызова внутри приложения — `app.ml.service.run_analysis`. На вход передаются
`AnalysisOptions` и ровно один источник: снимок или идентификатор истории.
Для JSON вместо backend допускается `None`. На выходе — JSON-совместимый словарь
версии 2. Экспорт через `export_result` атомарный и защищает исходный снимок.

Результат содержит `pipeline_version`, `fingerprint`, `implementation_fingerprint`,
`direction_profile_fingerprint`, `source_relations_fingerprint`, параметры, покрытие и `provenance`, включая
SHA-256 входного JSON. Для воспроизведения нужны тот же корпус, код, конфигурация,
параметры и зависимости из lock-файлов. Fingerprint позволяет сравнить условия
расчёта; он не является подтверждением научной корректности результата.

Стабильная схема: [result-v2.schema.json](../schemas/result-v2.schema.json).
Проверка сохранённого результата без загрузки модели:

```sh
.venv/bin/python -B -m tools.result_schema --result storage/delivery-photonic.json
```

Полная структурная сверка карточек, метрик, осей и исходных цитат:

```sh
.venv/bin/python -B -m tools.audit_ml_result --snapshot storage/ml-validation/corpus-portable.json --result storage/delivery-photonic.json --output-base storage/my-photonic-audit
```

Имя отчёта должно быть новым. Структурная сверка не заменяет содержательную
проверку назначения цитат; NMF при ней не обучается повторно.
Используйте результат, пересчитанный приведённой выше командой на текущем коде:
архивные результаты прежних версий сохраняют свои отпечатки и не заменяются автоматически.

Клиент будущей платформы должен проверять `schema_version`, читать все четыре
раздела и ограничения, учитывать `null` в неподтверждённых полях и не считать
пустой TOP технической ошибкой. Изменения смысла контракта должны сопровождаться
версией и интеграционными проверками. Этот модуль используется через Python API и CLI; веб-анализ реализован отдельно.

## Проверки

Полный набор запускается по [инструкции для своей ОС](checks.md#полный-набор-по-платформам).

Полный набор включает настоящий Tk: его нужно запускать в графическом окружении
с установленным Tcl/Tk, используя изоляцию процессов из [инструкции проверок](checks.md).
Дополнительно к тестам необходимы повторный расчёт на
неизменённых корпусах, сверка fingerprint/метрик, проверка происхождения цитат
и содержательная проверка выбранных полей. Числа текущего прогона следует брать
из его отчёта, а не из исторических разделов README или прежних аудитов.

Регрессионные тесты и разбор известных примеров не равны независимой оценке
точности. Для заявления о прогнозной способности нужны отдельные данные,
ретроспективное обучение только на прошлых годах и оценка на последующем окне
без переноса будущих документов в обучение. `precision@15` и lift нельзя
подменять долей пройденных программных тестов или получать из одних и тех же
примеров, по которым настраивался фильтр.
