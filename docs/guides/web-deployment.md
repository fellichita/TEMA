# Размещение веб-анализа на своём компьютере

## Подготовка из исходников

Сначала подготовьте основное окружение `.venv` и модели по
[инструкции запуска](../../README.md#ручная-подготовка-окружения).
Веб-интерфейс запускается в отдельном окружении. Из корня проекта:

```sh
python -m venv .venv-web
# macOS / Linux
.venv-web/bin/python -m pip install -r requirements/web.txt
```

На Windows последняя команда выглядит так:

```powershell
.venv-web\Scripts\python.exe -m pip install -r requirements/web.txt
```

Для работы только на своём компьютере, из активированного основного `.venv`:

```sh
python -m scripts.run_web_demo --local-only --no-auth --open-browser
```

На macOS файл `launchers/macos/web-local.command` выполняет подготовку окружений
и локальных моделей автоматически. Для публичного доступа используйте запуск
с туннелем, описанный ниже.

## Что доступно сейчас

У сервера пока нет домена и входящих портов 80/443. Поэтому запуск с прямым
публичным HTTPS-адресом сейчас невозможен. Штатный запуск веб-демо открывает
сайт через туннель (по умолчанию fxTunnel: `https://trendanalizer.fxtun.ru`); на
компьютере API и интерфейс слушают только `127.0.0.1`. Открывать входящие порты
для этого не требуется. Запускатель каждый раз создаёт отдельный случайный
пароль; пользовательский пароль из окружения для публичной ссылки не применяется.

На подготовленном компьютере запустите `launchers/macos/web-demo.command` (macOS),
`launchers/windows/web-demo.bat` (Windows) или из корня проекта:

```sh
.venv/bin/python -E -s -m scripts.run_web_demo
```

**Туннель по умолчанию — fxTunnel** (серверы в России, адрес
`https://trendanalizer.fxtun.ru`). Cloudflare из России с июня 2025 года режется
провайдерами: проходят первые ~16 КБ ответа, и сайт по `trycloudflare.com` у
российских посетителей не открывается. Один раз:

```powershell
irm https://fxtun.ru/install.ps1 | iex          # или клиент с GitHub mephistofox/fxtun.dev
fxtunnel login                                   # токен — в личном кабинете fxtun.ru
fxtunnel domains add trendanalizer               # закрепить постоянный поддомен
```

Другой поддомен — `--domain имя`, случайный — `--domain ""`. Для посетителей
вне России остаётся `--tunnel cloudflare` (нужен `cloudflared`; туннель идёт по
HTTP/2, потому что QUIC часто не проходит через прокси и VPN). Инспектор
трафика fxTunnel отключён: он записывал бы запросы посетителей, включая пароль.

Окно запуска печатает ссылку и пароль и кладёт их в
`storage/web-public-access.txt`; файл удаляется при остановке. Адрес fxTunnel
постоянный, пароль меняется при каждом запуске.

Публичная ссылка по умолчанию работает в отдельном профиле
`storage/web-public-profile`: история, библиотека и настройки владельца в нём
не видны. При первом запуске туда копируются модели из основного профиля
(около 2,5 ГБ); чего нет и там — скачивается. Ключи источников (например,
OpenAlex) берутся из системного хранилища этого компьютера и наружу не уходят.
Другой каталог можно задать `--data-dir`.

Если стандартные локальные порты заняты, добавьте два свободных порта, например
`--api-port 18000 --web-port 18501`. API и сайт всё равно останутся на
`127.0.0.1`. При сообщении `Could not lookup srv records` проверьте DNS,
VPN и сетевой прокси: туннель не получил адрес серверов Cloudflare.

Для отдельного Linux-сервера сначала создайте оба окружения и установите
зависимости и модели по [основной инструкции](../../README.md). Каталог данных
задавайте явно, вне исходников и виртуальных окружений. Окно процесса нужно
оставлять открытым: остановка процесса закрывает ссылку. После повторного
запуска ссылка и пароль меняются.

**Это доступ для испытаний, а не постоянная публикация.** Cloudflare прямо
ограничивает [Quick Tunnels](https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/do-more-with-tunnels/trycloudflare/)
сценариями разработки и тестирования: адрес временный, гарантии доступности нет,
действует лимит 200 одновременных запросов. Для постоянного сервиса понадобится
домен и управляемый Cloudflare Tunnel либо свой HTTPS-прокси.

**Защита данных посетителей.** Соединение шифрует туннель (HTTPS); страница,
открытая по `http://`, сама переходит на `https://` до ввода пароля. После
входа браузер получает случайный идентификатор посетителя, подписанный паролем
запуска (cookie на 12 часов, только для этого адреса). API помнит, какой
посетитель запустил какой анализ, и каждому отдаёт только его анализы: текущий,
историю, страницы `?run=…` и публикации. Анализ выполняется один за раз; пока
идёт чужой, остальные видят «сервис занят» без текста запроса. Связь
«посетитель — анализ» хранится в памяти процесса: после перезапуска меняются
ссылка и пароль, и прежние анализы остаются только в профиле на диске.

Это разделение браузеров, а не учётные записи: кто знает пароль, может войти,
а кто получил чужую cookie, увидит анализы её владельца. Без пароля (`--no-auth`)
разделения нет, поэтому такой режим допускается только на `127.0.0.1`.

## Панель управления

Любой запуск веба поднимает панель владельца на `http://127.0.0.1:8502`
(окно запуска печатает адрес; `launchers/windows/web-admin.bat` открывает её в
браузере, `--open-panel` — сразу при запуске). Она обновляется каждые 1,5 с и
показывает:

* сервер: работает / выключен / запускается (и на каком шаге) / упал — и кнопку
  **«Выключить сервер» / «Включить сервер»**. Выключение останавливает API,
  сайт и туннель, модели выгружаются из памяти; окно запуска и панель остаются.
  Включение поднимает всё заново с той же ссылкой и тем же паролем. Если сервис
  упал сам, окно больше не закрывается — панель показывает причину и включает
  сервер обратно;
* кто на сайте и **что делает сейчас**: на форме запроса, следит за своим
  анализом, смотрит результат, открыл историю, читает отчёт о технологии «…»,
  листает публикации; браузер, адрес (за туннелем — последний внешний адрес
  в `X-Forwarded-For`: клиент fxTunnel дописывает после него свой `127.0.0.1`),
  число анализов, «на сайте» или «ушёл N мин назад». Клик по посетителю
  открывает его карточку: лента действий с временем, его анализы и кнопки;
* текущий анализ: запрос, чей он, режим, часы и прогноз, пять фаз как на сайте,
  текущий этап с сообщением и счётчиком, хронология этапов с длительностями и
  кнопка «Остановить анализ» (работает для анализа любого гостя);
* рычаги над посетителями: **написать сообщение** (появится на его странице
  за ≤15 с), **выгнать** (сеанс завершён, cookie не пускает, нужен пароль),
  **заблокировать** браузер и внешний адрес (увидит «Доступ закрыт», его
  идущий анализ останавливается; адреса этого компьютера и локальной сети не
  блокируются), снять блокировку. Блокировки лежат в
  `storage/web-blocklist.json` и переживают перезапуски; без пароля и с новым
  адресом человек вернуться может — это не учётные записи;
* **приостановить новые анализы** (сайт и готовые результаты доступны, идущий
  анализ доживёт) и **сменить пароль** (перезапускается только сайт, все
  выходят и входят с новым паролем, модели остаются в памяти);
* журнал событий с фильтрами, фоновые задачи (перевод ТОПа, ТОП-15 технологий),
  последние анализы профиля с длительностью и ошибками, процессы с памятью,
  загрузку видеокарты (`nvidia-smi`), процессора, памяти и диска, готовность
  модели и ключей (без ключа OpenAlex — лимит 1000 запросов в сутки) и журнал
  туннеля (пароли прокси в нём скрыты).

Панель слушает только `127.0.0.1` и отвечает только на свой `Host`: туннель
ведёт на порт сайта, поэтому снаружи её не открыть. Сводку она берёт у API по
отдельному токену (`TREND_API_ADMIN_TOKEN`), которого нет у процесса сайта;
команды принимает только со своей страницы. Всё, что видит панель, живёт в
памяти: адреса и браузеры гостей на диск не пишутся, а после выключения
сервера журнал начинается заново. Другой порт — `--panel-port`, без панели —
`--no-panel` (тогда сбой сервиса, как раньше, закрывает окно).

### Вкладки «Анализы», «Источники и языки», «Обучение»

Над разделами панели — вкладки. «Обзор» — всё описанное выше.

* **«Анализы»** — все совершённые анализы профиля, а не только последние:
  поиск по запросу, трендам и технологиям, фильтры по состоянию, режиму,
  датам, стране материалов и источнику, «только с трендами / технологиями»,
  сортировка по дате, длительности, числу публикаций, трендов, технологий и
  доле отсеянного. Сверху — сводка выборки (готово и ошибок, публикаций по
  теме, средняя доля отсеянного, медианы режимов), ниже — активность за 30
  дней, частые запросы, технологии и тренды, повторяющиеся между анализами,
  вклад источников и стран. Флажками выбираются 2–6 анализов для сравнения
  (числа рядом, общие и собственные технологии и тренды) и для выгрузки в
  CSV/JSON. Клик по строке открывает результат для аналитика и все публикации
  анализа с оценкой темы (по теме / пограничная / не по теме, вклад смысла и
  слов); кнопки «✓ по теме» и «✕ мимо» — отметки владельца, самые весомые
  примеры для самообучения. Сводки анализов кешируются в
  `analysis-index.json` профиля и пересчитываются, только если анализ менялся.
* **«Источники и языки»** — страны, из источников которых брать сведения
  (ничего не выбрано — все страны; «Международные» — каталоги без одной страны),
  и переключатель каждого из 23 источников без ключей API. Правило лежит в
  `web-source-policy.json` профиля и записывается в каждый новый анализ, так
  что сохранённый результат помнит, что опрашивалось. Google News, GDELT и DOAJ
  ищут только в изданиях и журналах выбранных стран. Научный корпус анализа
  (Crossref, OpenAlex) международный и фильтром не ограничивается. Там же —
  **языки перевода**: русский встроен; другой язык добавляется из каталога
  (немецкий, французский, испанский, итальянский, китайский, японский,
  украинский, арабский, хинди, нидерландский, шведский) или своим кодом и
  моделью Hugging Face — экспортом ONNX модели Helsinki-NLP opus-mt
  «английский → язык». При добавлении программа один раз скачивает модель,
  закрепляет её ревизию и SHA-256 файлов (`models/translation-specs/` профиля)
  и дальше переводит без сети. Любой установленный язык можно сделать языком
  сайта; посетитель переключает язык карточек ТОПа сам.
* **«Обучение»** — самообучение на своих анализах: сколько примеров и из
  скольких анализов, качество модели на анализах, которых она не видела, в
  сравнении с одной эвристикой (AUC и доля верных решений, график по
  обучениям), слова, выдающие чужую тему, точность каждого источника и доля
  сбора, которую он получает. Переключатели: самообучение, переобучение после
  каждого анализа, адаптация долей источников. Кнопки: переобучить сейчас,
  обучить на прошлых анализах (собрать примеры анализов, сделанных до
  самообучения), сбросить модель (отметки владельца сохраняются). Всё хранится
  в каталоге `learning/` профиля.

### Одновременные анализы и очередь

Веб считает несколько анализов одновременно (по умолчанию два места). У
каждого гостя — один свой анализ; если все места заняты, новый встаёт в
очередь («Ваш анализ в очереди: перед вами N») и стартует сам, как только
место освободится. Ждущий анализ можно отменить; владелец убирает его из
очереди в панели. Каждый анализ идёт в своём потоке со своим соединением
SQLite; локальная модель одна на все анализы (вычисления по очереди, сетевые
этапы соседа идут в это время). Настольное приложение по-прежнему считает
один анализ за раз.

Раздел панели **«Ресурсы»** (файл `storage/web-resources.json`, переживает
перезапуски): число мест (1–4), пакет генерации модели (1–8), держать ли модель
в видеопамяти между анализами и кнопка «Выгрузить», глубокий режим для гостей,
длина очереди. Раздел **«Анализы»** показывает все идущие анализы с этапами и
очередь; клик по анализу (в том числе из «Последних анализов») открывает
результат глазами аналитика: цифры, оговорки (лимит OpenAlex, неполные
источники, пустой ТОП технологий), тренды с категорией и уверенностью, ТОП
технологий с вероятностью и публикациями внутри раскрывающихся карточек,
ближайшие исключённые с причинами, источники и время этапов. Если технологий
нет, панель показывает публикации отдельным списком.

### Что ускорено (замер 28.09.2026, «quantum sensors», быстрый режим)

* Именование тем — пакетами по 8 на GPU (55 → 36 с); ответы те же, что при
  генерации по одной.
* Годовой фон направления (OpenAlex) собирается в фоне с начала анализа
  (37 → 0 с ожидания).
* Анализ не ждёт ТОП-15 технологий: тот упирается в правило arXiv (запрос раз
  в 3 секунды) и досчитывается после публикации результата, сайт показывает его
  ход. Описания технологий переводятся ещё во время анализа.
* Готовый результат, перевод ТОПа и ТОП технологий собираются в момент
  окончания анализа, а не при первом опросе страницы (минус ~7 с ожидания).
* Модель Qwen остаётся загруженной между анализами.
* ТОП-15 технологий (замер на выборке «green hydrogen», 40 фраз подробной
  проверки): 202 → 32 с при том же результате. arXiv спрашивается пачками по
  8 фраз («фраза А ИЛИ фраза Б…», ответ раскладывается по фразам той же
  проверкой названия; неполный ответ дробит пачку); когда OpenAlex не ответил,
  одна пачка за всё время даёт и историю, и первое упоминание — 7 запросов
  вместо 80. Долгий отказ OpenAlex (исчерпан дневной бюджет без ключа,
  Retry-After — час) закрывает его до срока вместо ожиданий на каждой из 60
  фраз; панель показывает, на сколько он закрыт.

## Изоляция на сервере

Перед передачей ссылки другим людям:

1. Запускайте сервис от отдельного системного пользователя без прав администратора.
   Исходники, `.venv` и `.venv-web` должны принадлежать другому пользователю и
   быть доступны сервису **только для чтения**. Тогда сам веб-процесс не сможет
   переписать код даже при ошибке в обработке запроса. Модели в рабочем
   профиле проверяются по контрольным суммам; их обновление выполняйте отдельно.
2. Дайте сервису право записи только в отдельный каталог данных и необходимые
   ему системные временные каталоги. Не размещайте каталог данных внутри
   репозитория. Защищайте резервные копии и ключи отдельно.
3. Оставьте входящие порты 8000 и 8501 закрытыми в межсетевом экране. Нужен
   только исходящий доступ `cloudflared` к Cloudflare. Не публикуйте API через
   прокси и не запускайте публичный вариант с `--no-auth`.
4. Ограничьте память, число процессов и перезапуски средствами службы вашей ОС.
   Эти пределы зависят от установленной NVIDIA-карты, размера моделей и объёма
   одновременной работы; проверьте их нагрузочным испытанием до открытия доступа.

В коде уже ограничены размер входящих сообщений и загрузок, число одновременных
API-соединений и время ожидания сокета. Интерфейс обращается к API с отдельным
секретом запуска; API принимает только локальные соединения. Эти меры уменьшают
поверхность атаки, но не обещают неуязвимость к перегрузке публичного Streamlit.
На постоянном адресе потребуются правила ограничения запросов на внешнем
прокси и дополнительная проверка доступа до открытия WebSocket.

## Когда появится домен

Для прямого HTTPS направьте DNS-запись домена на публичный IP сервера и откройте
входящие 80/443 для HTTPS-прокси. [Caddy](https://caddyserver.com/docs/automatic-https)
может автоматически получить и обновлять сертификат при этих условиях;
[Streamlit](https://docs.streamlit.io/develop/concepts/configuration/https-support)
рекомендует завершать TLS на прокси. API останется на `127.0.0.1:8000`, а прокси
должен направлять только веб-интерфейс на `127.0.0.1:8501`. Перед переключением
запуска на постоянный домен нужно добавить его точное имя в `server.allowedHosts`
и проверить HTTPS, WebSocket, вход по паролю и ограничения нагрузки. Пока домена
и портов нет, этот режим не включён.

Вместо открытых портов можно оставить Cloudflare Tunnel, но для постоянной
ссылки нужна [управляемая конфигурация с собственным доменом](https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/get-started/create-remote-tunnel/).
