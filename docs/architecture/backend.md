# Backend: сбор и хранение публикаций и патентов

Backend работает самостоятельно через Python API или консоль.
Она не импортирует UI и ML, не формирует рейтинг трендов и не управляет лицензиями.

## Установка и запуск

Подготовьте Python 3.13 и проверенный SQLite по [основной инструкции](../../README.md).
Следующие команды выполняются в PowerShell из корня проекта:

```powershell
.\.venv\Scripts\python.exe -m app.backend --help
.\.venv\Scripts\python.exe -m app.backend sources
.\.venv\Scripts\python.exe -m app.backend --data-dir storage collect "neuromorphic computing" --sources crossref openalex --limit 20 --from-date 2024-01-01
.\.venv\Scripts\python.exe -m app.backend --data-dir storage collect "neuromorphic computing" --limit 20 --from-date 2024-01-01
.\.venv\Scripts\python.exe -m app.backend --data-dir storage jobs
.\.venv\Scripts\python.exe -m app.backend --data-dir storage documents --limit 5
```

Без `--data-dir` используется `%LOCALAPPDATA%\Trendanalizer Pilot main2`.
Имя каталога данных сохранено для доступа к существующей библиотеке.
Все вызовы для одного набора данных должны использовать одинаковый каталог.
`collect` обращается в интернет; `jobs` и `documents` работают только с локальной базой.
`versions` также читает локальную базу; `sources` показывает настройку доступа без сетевого запроса.
Ctrl+C отменяет текущий сбор. Команда дожидается выхода из текущего сетевого чтения.
Код завершения: 0 — успех, 1 — ошибка backend, 2 — неверные параметры, 130 — отмена с клавиатуры.

Сбор выводит JSON с ID задания, состоянием, числом просмотренных, сохранённых и
пропущенных записей, общим числом результатов источника и признаком полноты.
Успешная загрузка ограниченной выборки не означает полный охват направления.
`max_results` / `--limit` ограничивает просмотренные записи источника, включая невалидные.
Поэтому число сохранённых документов может быть меньше лимита.
При `--sources crossref openalex` лимит применяется отдельно к каждому источнику.
Результат содержит `all_succeeded` и список `jobs`; ошибка одного не останавливает остальные.
Сумма `stored` отдельных заданий не равна числу уникальных документов в общей базе.

## API для коллег

```python
from pathlib import Path
from app.backend.config import BackendSettings
from app.backend.contracts import SearchRequest
from app.backend.service import Backend

with Backend(BackendSettings(data_dir=Path("storage"))) as backend:
    job_id = backend.submit_collection(SearchRequest(
        topic="neuromorphic computing", max_results=100,
    ))
    # UI периодически вызывает backend.get_job(job_id).
    # Только в скрипте или вне потока интерфейса допустимо ожидание:
    job = backend.wait(job_id)
    records = backend.list_documents(job_id=job_id, limit=100, offset=0)
    for snapshot in records.items:
        print(snapshot.revision_id, snapshot.document.title)
```

| Метод | Назначение |
| --- | --- |
| `submit_collection(request)` | Поставить сбор в очередь и вернуть ID |
| `get_job(job_id)` | Прочитать состояние, счётчики и ошибку |
| `cancel(job_id)` | Запросить отмену; true означает, что сигнал принят, а не что задача уже остановилась |
| `wait(job_id, timeout=None)` | Дождаться результата; при истечении timeout задача продолжает работать |
| `collect(request)` | Синхронно запустить и дождаться сбора |
| `submit_collections(request, sources=("crossref", "openalex"))` | Поставить отдельное задание для каждого источника и вернуть их ID |
| `collect_many(request, sources=("crossref", "openalex"))` | Дождаться всех выбранных источников, включая ошибочные результаты |
| `sources()` | Показать источники и наличие ключей, без самих секретов и проверки доступа по сети |
| `list_document_versions(document_key, limit=100, offset=0)` | Получить неизменяемые версии документа, включая разные источники |
| `list_jobs(limit=50)` | Прочитать историю |
| `list_documents(job_id=None, query=None, limit=100, offset=0)` | Получить страницу документов |
| `close()` | Отменить незавершённые задания, дождаться закрытия worker и освободить блокировку |

У одного каталога данных один активный Backend. Он владеет очередью и блокировкой
на уровне ОС. Два объекта для разных каталогов независимы. Публичные API вызываются
пока контекст Backend открыт; конкурентный вызов close с другими операциями не поддерживается.
UI должен закрывать Backend вне основного потока окна, поскольку завершение может ждать
текущего сетевого чтения. Базовый read timeout — 15 секунд; проверка отмены между запросами и порциями ответа.

Форматы описаны в `app/backend/contracts.py`, версия контракта — 2.
`SearchRequest.source`: `crossref` (по умолчанию), `openalex`, `epo`.
Настройка и ограничения адаптеров: [SOURCES.md](backend-sources.md).
UI использует контракты `app/backend/contracts.py` и сервис `Backend`.
Эти же контракты доступны для подключения новой аналитики.

## Что сохраняется

- Нормализованные документы: DOI, название, аннотация, авторы, ссылка, тип и дата публикации.
- Для патентов: полный номер публикации с кодом вида и ID семейства, если источник его предоставил.
- Исходные метаданные каждой записи и время получения.
- Неизменяемые версии документов и ссылки на конкретные версии из каждого сбора.
- Поисковый запрос, временные ограничения, лимит, состояние задания и счётчики.

Одинаковый DOI не создаёт новый документ. Повторная загрузка без изменений не создаёт
новую версию только из-за времени получения. Изменённые метаданные создают новую версию;
результат старого сбора продолжает ссылаться на старый снимок. Точное время наблюдения
актуальности записи при повторном сборе связано с заданием и его периодом выполнения.
Внутри одного сбора фиксируется первая встретившаяся версия одного документа.
DOI объединяет записи Crossref и OpenAlex; без DOI используется ID внутри источника.
Нечёткое объединение по названию не выполняется. Патенты объединяются по полному
номеру публикации: EP1234567A1 и EP1234567B1 остаются разными документами,
даже если принадлежат одному семейству.

Поле `DocumentSnapshot.sources` в общей выдаче перечисляет найденные источники.
В снимке задания оно содержит только источник этого задания. Общая карточка показывает
последнюю сохранённую версию; поля разных источников автоматически не смешиваются.
Для выбора аннотации или сопоставления данных используйте `list_document_versions`.

`list_documents` также принимает `sort_by="default"|"title"|"date"|"citations"`
и `descending=False|True`. Сортировка выполняется до пагинации, в общей библиотеке,
задании и историческом сборе. `default` сохраняет прежний порядок независимо от
`descending`. Названия сравниваются без учёта регистра, включая кириллицу.
Неизвестные числовые значения и компоненты даты идут после известных в обоих
направлениях; при совпадении значений порядок стабилизируется ключом документа.
Изменения схемы базы не требуется.

Поиск `query` — буквальная подстрока названия/аннотации без учёта регистра,
включая русский язык; это не семантический поиск. Выдача ограничена страницей до 1000 записей.
Без job_id показываются последние версии документов. Для входного набора ML
используйте job_id, чтобы обновления базы не меняли набор незаметно.

Схема SQLite имеет номер версии. Более новая, неизвестная схема отклоняется.
Текущая схема — 4. Перед переходом со старой версии автоматически создаётся согласованная
резервная копия `documents.sqlite3.before-v4-<id>.bak` рядом с базой. Старые задания
сохраняют свою версию контракта, новые получают 2; старые payload и ревизии не переписываются.
Каждая страница сохраняется одной транзакцией. Сеть не держит транзакцию открытой.
При аварийном завершении следующий владелец backend помечает задания queued/running
как interrupted. Автоматическое продолжение курсора после перезапуска пока не реализовано;
повторный сбор дедуплицирует уже сохранённые документы.
Для длительных загрузок есть отдельный исторический сбор: план по месяцам или годам,
прогресс, отмена, продолжение незавершённых периодов и отчёт о полноте.
Команды и новый Python API описаны в [руководстве исторического сбора](../guides/history-collection.md).

## Интернет и ограничения данных

Подключены Crossref REST API и OpenAlex; добавлен адаптер EPO OPS с обязательными ключами.
Адреса API фиксированы в коннекторах; живой доступ EPO без ключей не проверен.
Для Crossref запрос явно задаёт `sort=relevance&order=desc`, включая страницы с курсором.
Передаётся только направление и параметры поиска. Приложение не передаёт на сервер
локальную базу. Ключей API у Crossref нет. OpenAlex поддерживает необязательный ключ;
EPO требует пару ключ/секрет. Они читаются только из окружения процесса и передаются
в заголовках авторизации, а не в URL или сохранённых настройках. Системное хранилище
секретов Windows пока не подключено; `.env` автоматически не читается.

Пагинация, ограниченные повторы временных сбоев, Retry-After, межстраничная пауза,
таймауты, общий дедлайн страницы, лимиты сетевого и распакованного ответа предусмотрены.
Редиректы не выполняются; сертификаты HTTPS проверяются. Полные HTTP-ошибки не попадают
в сохраняемые сообщения задания. HTML/JATS в названии и аннотации преобразуется в текст.

Часть записей Crossref не содержит аннотаций. Пропуски не заполняются выдуманным текстом.
Если известен только год или месяц, полный день публикации не придумывается;
исходные date-parts остаются в raw_metadata. Запрос на русском принимается без перевода:
выдача зависит от индексирования источника. Расширение запроса и проверка тематической
релевантности относятся к отдельной будущей интеграции.

Это выборка поисковой выдачи, а не полный исторический корпус для расчёта роста.
`total_available` — оценка числа результатов источника, а не число подтверждённых
публикаций по тренду. Перед вычислением динамики нужно отдельно обеспечить сопоставимый
охват по годам. Расчёт рейтинга и AI выполняются отдельными модулями приложения.
Патентный адаптер проверен на фиксированных ответах; для приёмки реального сбора нужен доступ EPO.

## Проверки и производительность

```powershell
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m scripts.benchmark_backend --records 10000
```

Тесты коннектора используют HTTPX MockTransport и не требуют сети. Проверяются ошибки,
лимиты, отмена, состояния, версии документов и повторная загрузка.
Исторический сбор, продолжение и учёт полноты периодов: [исторический сбор](../guides/history-collection.md).
Компактный прогресс для клиента: `get_history_progress(id)`; читаемый отчёт в консоли:
`python -m app.backend --data-dir storage history <ID> --format text`.
Benchmark использует синтетические документы и временную БД: отдельно измеряет
первую и повторную запись, локальный поиск и пик Python-выделений памяти.
Этот показатель не равен RSS процесса и не включает все нативные буферы SQLite.

Код C пока не добавляется. SQLite уже выполняет операции хранения в нативном коде.
Сначала профилируем реальные загрузки и запросы; выделение собственного нативного
модуля имеет смысл после обнаружения конкретного вычислительного узкого места.

Практическое упрощение относительно первоначального плана: SQLite подключена через
драйвер `app.sqlite_runtime` с версией схемы, зависимости закреплены в lock-файлах.
SQLAlchemy, Alembic и uv сейчас не используются. Полнотекстовый индекс, составные
исторические выборки и дальнейшие миграции добавляются по мере появления рабочих сценариев.

Официальная документация источника:
https://www.crossref.org/documentation/retrieve-metadata/rest-api/tips-for-using-the-crossref-rest-api/

SQLite в Python: https://docs.python.org/3/library/sqlite3.html
Профилирование: https://docs.python.org/3/library/profile.html
