# Десктопный интерфейс: сбор, документы и локальные тренды

Устройство интерфейса, палитра, типографика и правила компонентов описаны в
[дизайн-системе](../design/overview.md).

Подготовьте окружение по [основной инструкции](../../README.md), затем запустите
приложение из корня проекта:

```powershell
# Windows
.\.venv\Scripts\python.exe -m app.main
```

```sh
# macOS / Linux
.venv/bin/python -m app.main
```

Нужен Python 3.13 с Tcl/Tk. Аргумент `--data-dir` позволяет выбрать отдельную
библиотеку. Без него используется системный каталог приложения; его имя
`Trendanalizer Pilot main2` сохранено для совместимости с существующими данными.
CLI и UI должны использовать одинаковый каталог для доступа к одним документам.
Один каталог допускает только одного активного владельца Backend.

## Что доступно

- «Документы»: полный сохранённый объект в карточке, поиск подстроки названия и
  аннотации, страницы по 50 документов. Сортировка всей выборки по названию, дате
  публикации или цитированиям в обоих направлениях; также доступен порядок backend
  по умолчанию. Смена сортировки возвращает на первую страницу и сохраняет поиск
  и выбранное задание/исторический сбор. Неизвестные значения идут после известных; неполные даты
  не дополняются выдуманными днями. Внутри одинакового года/месяца более точные
  даты идут раньше неполных в обоих направлениях.
- «Разовый сбор»: тема, даты, лимит, один или несколько источников. Пустая конечная
  дата означает сегодня UTC. Начальная дата необязательна.
- Отдельная вкладка «Процессы», последние 100 заданий: состояние, просмотренные/сохранённые/пропущенные записи,
  ошибка, отмена, переход к сохранённым документам задания.
- «Повторить с этими параметрами» переносит запрос выбранного задания в форму,
  включая исходную конечную дату. Новый сбор запускается кнопкой «Начать разовый сбор».
- Вкладка «Источники» показывает настройки доступа и ограничения без сетевого запроса.
  Названия Crossref, OpenAlex и EPO — ссылки на их сайты; доступны мышью, Enter
  и пробелом после перехода клавишей Tab.
- Записи появляются после сохранения страницы. Нет выдуманного процента выполнения.
  Успешный сбор с неполным охватом помечается отдельно.
- Карточка показывает отсутствующие поля и неполные даты без подстановки выдуманных
  значений. Кнопка источника открывает внешний браузер; текст ссылки можно скопировать.
- При запуске читается сохранённая база без сетевого запроса. Отсутствие интернета
  не мешает просмотру и поиску. Загрузка новых документов требует сети.
- При закрытии окно ждёт отмены и завершения фоновой работы, оставаясь отзывчивым.
  Повторное открытие вызывает штатное восстановление backend.

## Локальный анализ из интерфейса

Вкладка «Тренды · MVP» принимает направление и период из 4–30 полных лет.
Можно собрать годовую историю OpenAlex/Crossref, выбрать сохранённую историю,
открыть JSON-снимок корпуса или запустить локальное демо. Расчёт выполняется
в отдельном потоке и не блокирует просмотр документов.

Результаты разделены на основной TOP, предварительные сигналы, устойчивые
направления и исключённые группы. В карточках доступны динамика, проблема,
преимущество, пример, фрагменты источников и ссылки. Основной TOP содержит
до 15 карточек, которые прошли проверки; неподтверждённые группы его не дополняют.
На вкладке «Качество данных и методика» видны причины исключений и ограничения
покрытия. «Сохранить результат JSON…» экспортирует все разделы и диагностику.

Для загрузки нужен JSON-снимок корпуса, а не результат анализа. Ошибка загрузки
не закрывает окно; можно выбрать другой файл и повторить. Пошаговый сценарий — в
[руководстве локального анализа](../guides/local-analysis.md). Продолжение исторического сбора доступно во вкладке
«Сбор по периодам», его экспорт — через [backend API/CLI](../guides/history-collection.md).

EPO включается только при наличии `EPO_OPS_KEY` и `EPO_OPS_SECRET` в окружении
до запуска приложения. Интерфейс не сохраняет ключи и не заявляет, что наличие
настроек доказывает доступ по сети. Для EPO сохраняется ограничение 2000 записей.

Клавиатура: Tab/Shift+Tab — переход между элементами, Ctrl+F — поиск,
Enter в поиске — выполнить запрос, F5 — перечитать документы. Форма прокручивается
и автоматически показывает поле, получившее клавиатурный фокус.

## Версии документов

Выберите документ и нажмите «Сохранённые версии». Отдельное окно показывает
версии всех источников страницами по 50, их даты и время получения. Выбор версии
открывает её собственную карточку и исходные метаданные; ссылка ведёт к источнику
именно этой версии. Версия исходной карточки отмечается, если она присутствует
на открытой странице. Просмотр не меняет снимок документа в задании.

## Исторические сборы

Во вкладке «Сбор по периодам» доступны список последних 100 сборов и открытие
более старого по ID. Выберите строку и нажмите «Показать периоды выбранного сбора»
(или дважды нажмите строку). На странице «Периоды и прогресс» доступны параметры
сохранённого плана, выполнение, полнота, периоды и действия над сбором.

«Создать сбор по периодам» открывает прокручиваемую форму: тема, обязательное начало,
окончание (пустое — сегодня UTC), источники, месяцы/годы, лимит на период и источник,
автоматическое дробление и максимум узлов плана. Backend повторно проверяет
параметры через HistoryRequest. Создание фиксирует конечную дату и сохраняет план.

- Отмена запрашивается у backend и не означает мгновенной остановки сетевого чтения.
- «Продолжить» использует тот же план. Полные периоды сохраняются; незавершённые
  запускаются с начала периода. Флажок «Повторить также неполные периоды» передаёт
  `retry_incomplete=True`; лимит сам не увеличивается. Переполненные периоды могут
  дробиться в соответствии с сохранёнными настройками. Подробнее: [исторический сбор](../guides/history-collection.md).
- Процент показывает обработку конечных периодов. 100% не гарантирует полноту
  данных; после дробления процент может уменьшиться. Неизвестные счётчики показаны
  знаком `?`. Сохранённые записи разных источников и родителей не суммируются.
- Разделённые родители показаны вместе с дочерними периодами с отступами. Детали
  периода содержат полноту, причину неполноты, действующий лимит и число попыток.
- «Документы сбора» открывает объединённую выборку последних попыток конечных
  периодов. Родительские выборки после дробления в неё не входят. Состав может
  изменяться после продолжения. «Все попытки периода» позволяет открыть документы
  любой старой попытки; они сохраняют свои версии.
- Переход к другой выборке сбрасывает текст поиска и страницу, сохраняет сортировку.
  После перехода поиск и сортировка работают внутри выбранного сбора или задания.
- Список и прогресс обновляются при открытой вкладке исторических сборов и при
  просмотре их документов. При закрытии дочерних окон поздние ответы игнорируются.
  Закрытие приложения отменяет фоновые задания через штатный Backend.close.

Просмотр сохранённых планов, документов, попыток и версий работает без сети.
После аварийного завершения загрузка автоматически не возобновляется — используйте
«Продолжить». Новая функциональность использует готовый backend без изменения
схемы базы или логики сбора.

## Структура

- `app/ui/window.py`: окно, список, форма, карточка, задания, состояние навигации.
- `app/ui/trends_panel.py`: форма направления, история, разделы результатов,
  качество данных, отмена анализа и экспорт. Карточки содержат текст источника
  без автоперевода.
- `app/ui/versions.py`: просмотр неизменяемых версий и исходных метаданных.
- `app/ui/history.py`: форма, список планов, прогресс, параметры и попытки периодов.
- `app/ui/controller.py`: последовательные вызовы Backend в отдельном потоке
  и отдельный исполнитель локального ML;
  обработчики результатов выполняются только в потоке Tk. Повторный опрос не
  накапливается в очереди. Закрытие идёт после уже отправленных вызовов.
  ML использует отдельный рабочий поток, чтобы просмотр документов оставался доступен.
- `app/ui/presentation.py`: подписи, форматирование и предварительная проверка формы.
  Backend повторно проверяет запрос через SearchRequest или HistoryRequest.
- `app/ml/service.py`: проверка входного корпуса, локальный расчёт и экспорт JSON.

Для сортировки расширен `list_documents`: необязательные `sort_by` и `descending`.
Схема базы и прежний порядок по умолчанию сохранены. Версии документов и
исторические сборы подключены через существующие методы Backend.

## Проверки

На macOS/Linux запускайте актуальный runner из корня проекта:

```sh
.venv/bin/python -m pip install -r requirements/dev.lock -r requirements/semantic.lock
.venv/bin/python -m tools.run_checks --mode gui
```

Runner запускает каждый GUI-сценарий отдельным процессом с timeout, включая TkCase
за пределами `tests/ui`. Для Linux без дисплея нужен Xvfb; инструкции, отчёты и
платформенные ограничения описаны в [инструкции проверок](../guides/checks.md).

UI-тесты работают с настоящим окном Tk и тестовым backend без сети:
пагинация, поиск, устаревшие ответы, частичные результаты, ошибки, отмена,
перезапуск после ошибки открытия, потоки и отзывчивое закрытие.
Интеграционная проверка использует настоящий Backend: сбор из формы, сохранение,
анализ, карточки, экспорт, повторный выбор истории, закрытие и чтение без сети.
Это не заменяет проверку живых источников и установленного production-окружения.

Проверки версий и исторических сборов находятся в `tests/ui/test_history_versions.py`:
повтор неполного периода, отмена и продолжение, дробление, старые попытки,
неизменяемость версий, разные источники, офлайн-открытие сохранённого плана,
ошибки чтения, закрытие окна во время запроса и защита от устаревшего прогресса.
Отдельная проверка открывает окно размером 940×740 и форму 650×420 и проверяет
доступность действий. Это функциональная проверка компоновки, не приёмка дизайна.
На macOS оконные сценарии запускаются раздельно, например:

```sh
python -m pytest tests/ui/test_history_versions.py::HistoryIntegrationTests::test_retry_versions_attempts_and_offline_reopen -q
```

## 4K, Retina и масштаб интерфейса

Масштаб выбирается при запуске. На Windows приложение включает системную DPI-aware
отрисовку до создания окна; размеры контролов следуют системному масштабу.
На Linux используется масштаб, который сообщает Tk. На macOS используются
логические координаты Aqua — Retina не вызывает повторного увеличения вдвое.
Масштабируются отступы, размеры окон и колонок, высота строк, скругления и значки;
размеры текстовых полей в символах и строках сохраняются.

При необходимости задайте масштаб явно (допустимо 0.75–3.0):

```sh
.venv/bin/python -m app.main --data-dir storage --ui-scale 2
```

`--ui-scale 1.5` соответствует 150%, `--ui-scale 2` — 200%. Это абсолютный масштаб
интерфейса, а не дополнительный множитель поверх системного. Без аргумента
используется автоматический выбор. Разрешение 3840×2160 само по себе не задаёт
удобный размер текста: учитывайте физический размер экрана и системный DPI.

На Tk 8.6 автоматическая смена DPI при переносе окна между мониторами с разным
масштабом не гарантируется. После смены монитора перезапустите приложение;
при необходимости задайте `--ui-scale`. Очень крупный масштаб на небольшом экране
может сделать плотные панели тесными; границы начального окна ограничены экраном.

## Мониторы 120/144 Гц

Приложение сохраняет событийную отрисовку Tk. Прокрутка форм учитывает величину
движения и дробные события, объединяет серии ввода в ближайшем idle-цикле и не
использует фиксированный таймер на 60 Гц. Поддерживаются колесо, трекпад и Linux
Button-4/Button-5. Отрисовка таблиц и текстовых полей остаётся штатной для Tk.
Таймеры чтения фоновых результатов и прогресса не являются частотой кадров.

Частота дисплея выбирается в настройках ОС. Tkinter не предоставляет гарантии
120/144 FPS или управления VSync: фактическая частота вывода зависит от версии Tk,
ОС и оборудования. Автотесты проверяют масштабирование и обработку серий событий,
а не физическую частоту кадров. Физические 4K/120/144-Гц мониторы в текущей проверке
не использовались.
